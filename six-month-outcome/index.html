Research outcomeUpdated 28 October 2026

Six-month outcome: a defensible path from battery files to research decisions

The main result is not a universal battery model. It is a working, evidence-led framework that shows which datasets can be used, which claims are not yet supported, and what experiment is needed next.

Plain-language conclusion: The project has established the workflow for linking battery time-series, EIS, and DRT analysis. It has also shown that a fixed model does not transfer reliably across unrelated datasets. This negative result is useful: it prevents an unsupported generalisation claim and narrows the next study to a controlled, matched experiment.

Research target and decision rules

A TS–EIS–DRT dataset is accepted only when cell identity, state, temperature, units, protocol, and a join rule are evidenced. This replaces informal file matching with a repeatable screening process.

What has been achieved

Six concrete research outputs

  1. Dataset screening framework: candidate datasets are classified by what they genuinely support: time-series, EIS, DRT preparation, cell-level association, or state-level matching.
  2. Source audit discipline: manifests now record provenance, licences, identifiers, units, test context, and the exact reason a dataset is accepted, held, or rejected.
  3. CALB evidence package: the local package contains a 264-row manifest across 11 processed cells, eight protocols, and 10, 25, and 40 degrees C conditions. It provides an internal evidence base for pulse, drive-cycle, and measured-EIS comparison.
  4. EIS quality metadata: a finite-range Kramers-Kronig consistency screen was run on 21,366 rows; 20,961 rows passed the configured residual screen. The result is recorded as quality metadata, not as proof that a prediction model is valid.
  5. Reproducible pipeline demonstration: the demo pipeline documents objective, method, scoring, results, code, and data. On its controlled demo input, the recorded model RMSE was 0.00798 ohm versus 0.00921 ohm for its baseline. This demonstrates the software path, not broad scientific generalisation.
  6. External-testing boundary: frozen external checks recorded where the fixed method does not have support. The project therefore has an auditable answer to both positive and negative outcomes.

Scientific interpretation

The key finding is about experimental context

Time-series and EIS data are not automatically compatible because they come from the same battery type or the same archive. The useful unit of analysis is a documented measurement relationship: the same cell, a known state of charge, temperature, ageing condition, and test protocol. The negative cross-dataset results show why this requirement matters.

DRT is therefore used as an analysis output for quality-checked EIS spectra, alongside reconstruction, residual, stability, and uncertainty checks. It is not treated as an automatic label produced from any CSV file.

What remains open

Boundaries of the current result

  • No universal TS-to-EIS or TS-to-DRT model has been demonstrated.
  • Cell-level associations do not by themselves prove event-level or state-level measurement pairing.
  • Kramers-Kronig consistency is an EIS quality screen; it is not a substitute for DRT uncertainty or external model validation.
  • The local API/HPC workflow is operational as a demonstration. A remote VM/HPC run remains a deployment task and requires separately verified access.
Decision for the next phase

Do less, but make the evidence stronger

  1. Choose one source with explicit same-cell and state metadata.
  2. Freeze a small manifest before modelling.
  3. Run EIS quality, DRT reconstruction, stability, and uncertainty checks with saved settings.
  4. Compare against a simple baseline on held-out cells or an independent matched set.
  5. Report either support, partial support, no support, or inconclusive status without post-result tuning.
