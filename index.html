Researcher snapshot

What this work is about

The goal is not to claim a universal battery model. The goal is to create a traceable path from source files to a justified decision: accept a dataset, reject it, or identify exactly what metadata is still missing.

TScycling and pulse time-series
EISmeasured impedance spectra
DRTreproducibility-focused analysis
Auditsource, units, IDs, and join evidence
How I work

Research method, kept visible

01

Inspect the source

Record file structure, variables, units, identifiers, protocols, and available operating conditions before analysis.

02

Test the link

Only pair TS and EIS when a cell, state, temperature, protocol, and acquisition relationship can be evidenced.

03

Publish the decision

Report successful paths, rejected candidates, and limitations so the next step can be independently checked.

Current pipeline progress

Four research stages completedNext study not started
Versions 1 to 3: complete

Early transfer attempts were tested and closed. None produced reliable outside support.

Version 4: complete

Passed one narrow locked test on three Oxford NCA cells at 24 C and 50% state of charge.

Version 5: complete

Failed the locked SiCWell test. The safety guard rejected all 892 rows before prediction.

Version 6: complete

No universal zero-shot or small-calibration candidate passed every dataset-level gate. This path is stopped.

Now: blocked before launch

The next step is a narrower controlled study, not Version 7. It cannot start until the lab confirms matching cells, equipment, safety approval, channels, calibration, operator access, and schedule.

Important: “complete” means the stage reached a recorded decision. It does not mean the model succeeded.

How the versions connect

Version 4 fixed scaling

It passed one narrow external test, but the health step still used measured EIS.

Version 5 fixed the chain

It predicted EIS before health, then failed its frozen SiCWell external test.

Version 6 tested rescue options

Representations, small calibration, guards, and uncertainty did not produce a universal candidate.

The next study narrows the domain

One exact cell model, one lot, one protocol, and a locked cell-level evaluation.

Keep the studies separate

Main cross-dataset study: tests whether partial battery measurements can recover missing EIS and health information. Versions 4, 5, and 6 must be read together.

Backup CALB study: compares pulse data with measured EIS from the same CALB testing campaign. It is internal evidence, not validation with other cells.

LG M50T Expt 4: studies drive-cycle ageing health features. It is not EIS external validation.

Internal evidence
 Parsed the archive, published viewable data files, built the internal pulse-to-EIS evidence package, and kept the drive-cycle limitation visible. The drive-cycle result is weaker than the HPPC/EIS bridge. Do not flatten those into one claim. Open CALB readiness report
Distribution of Relaxation Times pipeline
Method-development outputs
 Time-domain battery pipeline that finds pulse/rest windows, fits relaxation behavior, compares against EIS, and reports where voltage-only fitting can look good while still failing impedance behavior. This is method development. Strong voltage fit is not automatically strong impedance evidence. Open DRT method outputs
